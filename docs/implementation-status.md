# Implementation status

Last updated 2026-10-19 (chat-service). "Verified" means the check was executed and passed in the session named below;
anything not executed is listed as unverified, not as working.

## Verification environment

A Linux cloud VM: 2 vCPU, 7.6 GB RAM, Java 21, Maven 3.9, Node 22, PostgreSQL 16, Apache Kafka 3.9.1 (KRaft,
single node) and Redis 7 running as local processes. Docker was available, but **no container registry was
reachable**, so no image could be pulled or built. Services ran as plain `java -jar` processes with the
environment variables from `docker-compose.yml`.

## Feature status

### Verified (automated tests and live runs)

- Registration, sign-in, refresh-token rotation with reuse detection, password change and reset, account lock,
  login throttling, JWKS, bootstrap administrator.
- Seller application, approval with automatic VENDOR role, rejection, suspension, reinstatement, commission.
- Product lifecycle with variants and images, moderation (block/unblock), categories, full-text search,
  Redis cache-aside with invalidation.
- Inventory: conditional reservations, all-or-nothing multi-line, expiry, confirmation, release with tombstone,
  restock, adjustments, thresholds, low-stock alerts, movement ledger, ledger check.
- Checkout: server-side pricing, coupons, multi-vendor split, idempotency keys, the full saga and every
  compensation path listed in the README, timeouts and retries, cancellation with refund and restock.
- Payments: authorise/capture/void/refund, time limiter, circuit breaker and bulkhead, unknown outcomes with
  reconciliation, signed webhooks with replay protection, late-outcome void/refund.
- Notifications: e-mail through retry topics and DLT, in-app inbox, deduplication.
- Reviews: verified purchase only, one per product, moderation, rating aggregation to catalog.
- Vendor earnings ledger and payouts; analytics read models; audit log; dead-letter register.
- Gateway: JWT validation, role rules, CORS, security headers, rate limiting, circuit breakers with logged causes,
  correlation ids, request size limit.
- Frontend: storefront, cart, checkout, order tracking, account pages, seller hub, admin console, all calling the
  real APIs (covered by the Playwright suite for the main journeys and by manual screenshots for the rest).

### Implemented but not verified

- **Docker images and the Compose stack** were never built or started (no registry access). Expect possible
  first-run issues such as image tags or health-check timing.
- **Helm chart** was never installed on a cluster; only rendered and schema-validated as described above.
- **GitHub Actions** workflows (CI and nightly e2e) have not run.
- **OpenTelemetry tracing**: configured (OTLP exporter, Kafka and HTTP observation enabled), but no trace was
  inspected in Jaeger because Jaeger could not be run.
- **SMTP delivery** to Mailpit: verified with the log-mode mail sender and in integration tests; not against a
  real Mailpit container.
- Seller and admin pages not covered by Playwright (e.g. product editor image upload, category editing, review
  moderation) were exercised through their APIs in integration tests and checked visually, but have no
  browser test.

### Not implemented

- A real payment provider adapter (the sandbox provider implements the same port).
- Multi-currency, regional tax rules, seller-specific shipping rates.
- Object storage for product images (local volume only).
- Automatic pruning of `processed_event`, the audit log and old analytics facts.
- Real-time push to the browser (order progress is polled).

## Known dependency advisories

- `react-router-dom` 6.30.6 (production): two moderate advisories fixed only in React Router 7. One concerns
  open redirects through backslashes in `<Link>`/`useNavigate`; MarketFlow navigates to user-supplied targets in
  exactly one place (`?next=` after sign-in), which `src/lib/redirect.ts` validates and rejects backslashes and
  control characters (`redirect.test.ts`). The other concerns server-side rendering, which is not used.
  Migration to React Router 7 is a follow-up.
- Development tooling only (not shipped): Tailwind CSS 3's file watcher dependencies and Vitest 3 have
  high/critical advisories fixed in Tailwind 4 and Vitest 4. Vitest 4 could not be installed in this
  environment (npm resolver error on its peer dependencies). Both are major migrations left as follow-ups.

## Defects found during verification (fixed)

| Found by | Defect | Fix |
|---|---|---|
| k6, 50 VUs | Spring Cloud CircuitBreaker's default bulkhead (25 concurrent calls) rejected requests and the rejections opened the catalog circuit breaker: 16 % of requests failed with 503 | bulkhead sized to 150, `BulkheadFullException` ignored by the breaker, fallback logs the cause |
| k6 | pooled gateway connections outlived Tomcat's 10 s keep-alive ("prematurely closed") | pool idle eviction at 20 s, Tomcat keep-alive 30 s |
| k6 | saga p95 4.3 s dominated by 500 ms outbox polling across 8 hops | poll interval 100 ms (p95 1.1 s) |
| clean install | a consumer that started before the producer created its topic was assigned partition 0 only and missed events on partitions 1-2 for minutes (a seller's approval did not grant the VENDOR role) | every service declares the topics it consumes as well as produces (`DeclaredTopicsTest`) |
| Prometheus | lazily created DLT counters started at 1, so `increase()` never saw the first dead letter after a restart and the alert could not fire | counters registered at 0 at start-up; alert verified firing |
| Playwright | checkout rendered the "new address" form while saved addresses were loading, then swapped it out | address section waits for the addresses; Place order disabled until loaded |
| npm audit | React Router 6.30.1 open-redirect advisory (high) | upgraded to 6.30.6; redirect guard hardened |
| analytics | the dead-letter register stored the wrapper exception instead of the root cause | stores `kafka_dlt-exception-cause-fqcn` (class names only, no messages) |
| API e2e | script was throttled by the gateway's default rate limit | catalog lookups cached, 429 retried with backoff (safe: rejected before reaching any service) |
